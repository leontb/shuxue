## 1. 状态与时间

至少区分三层：

| 层 | 负责什么 | 不应包含什么 |
|---|---|---|
| 数学模型 | 给定时刻/条件后的真实量、方向、边界 | DOM、定时器、按钮状态 |
| 教学状态 | 当前步骤、选择、是否答对、已解锁、训练进度 | 把动画帧数当真实运动时间 |
| 展示状态 | 播放进度、暂停、关键帧、缩放、焦点 | 重新计算一套不同答案 |

数学时间例如t＝11秒，与播放经过的真实秒数不同。加快/放慢播放时，显示的t和所有读数仍来自同一数学函数。必要时标注播放倍率。

## 2. 自动推进

### 核心状态转换

- 未作答 → 选错：保留本步，显示原因，允许再选。
- 未作答/选错 → 选对：标记正确，排定一次600毫秒后的推进。
- 等待推进 → 新操作：取消旧推进，执行新操作。
- 等待推进 → 超时且条件仍有效：仅推进一个步骤。
- 最后一个讲解步骤答对 → 进入训练一。
- 训练一答对 → 进入训练二。
- 训练二答对 → 显示完成，停止推进。

保留“上一步”“重播”“从头开始”。默认不需要“下一步”。查看提示或解析本身不当作答对。

### 计时器边界

使用单独的自动推进计时器，不与动画帧或动画延时共用清理数组。否则暂停动画可能意外取消答题推进，或重播后残留旧跳转。

计时器回调至少重新确认：

- 当前步骤仍是原步骤。
- 当前答案仍正确。
- 没有发生更新的选择或导航。
- 页面处于可交互状态。

可以用递增token加clearTimeout。不能只靠按钮禁用掩盖竞态。

### 必须取消的情况

新选择、重复点击、返回、直接切步骤、重播、重置、展开解析、切到其他训练、页面隐藏或卸载。
取消后保持可恢复：再次点选正确项可以继续。

在document捕获阶段取消旧计时器，再在具体按钮处理器中创建新计时器，是一种可选实现。若使用冒泡监听，注意重绘可能已把旧按钮移出DOM，不能只靠closest判断事件来自哪里。使用稳定DOM、事件标记或原按钮dataset。

键盘激活与鼠标点击走相同路径。推进后将焦点移到新步骤标题，避免焦点丢到页面顶部或已删除的节点。

### 反馈时长

600毫秒是短确认时间，不是阅读完整推导的时间。长期可见的图示、展开解析和回看入口必须承载关键理由。减少动态效果只影响动画，不改变答题自动推进规则。

## 3. 数学动画

以纯函数返回完整状态，例如：

```js
stateAt(t) => {p, m, q, n, direction, gap}
```

渲染层只消费状态。用同一个值更新点的位置、标签、数字、颜色和说明。

保留以下不变量：
- 比例图各等份真的等宽，所示长度与数量关系一致。
- 线段恒长，中点始终位于两端平均值。
- 折返时位置连续，方向切换正确。
- 正负坐标、实际路程、速度与时间单位不混用。
- 在相遇和折返附近提供精确关键帧，不靠视觉采样确定答案。
- 用完整区间分析排除其他解，不能用动画只播放到某时刻来暗示全程结束。

重播先终止旧requestAnimationFrame，再从指定状态开始；结束时停在精确终点。每次离开步骤调用清理函数。

优先HTML/CSS/SVG绘制精确数学图。位图可用于非必要插图，但不能用生成式图像承载精确标尺、几何或数值。

## 4. 下载与离线

单文件HTML必须内嵌所需CSS、JS、SVG。默认不请求字体、CDN、API、远程图片和本地相邻文件。

导出时：
1. 保留全部应用脚本及配置。
2. 排除预览宿主注入的脚本、base标签、调试页面和账号信息。
3. 清除临时DOM或由应用初始化重建初始状态。
4. 不把已选择答案、动画进度、待执行计时器写成下次打开后的状态。
5. 创建Blob和下载链接，完成后释放Object URL。
6. 下载失败给出简短说明和备用文件获取方式。

先做一个下载按钮并不等于下载功能已验证：必须打开导出的文件，重新走一遍交互。

## 5. 布局与可访问性

- 检查320/360像素窄屏与桌面；优先检查最密集图形，不只看首页。
- 正文字号通常14～18像素，按钮至少约40像素高；根据实际内容调整。
- 小屏图不要简单整体缩小。重排标签、隐藏重复坐标、保留独立数值卡、做局部放大。
- 给SVG设置明确的文字描述；颜色之外保留点名、箭头或形状。
- 选项使用原生button，标明选择状态，支持键盘。
- 反馈使用适度aria-live，不让每帧坐标更新频繁打断读屏。
- 适配prefers-reduced-motion，仍能点选全部关键帧和获取完整推理。
- 原题可以折叠；主讲解逐步显示；总结与训练各有明确入口。
- 多步动画中保留“现在显示什么”的短说明，避免学生只看到移动却不知道观察目标。

## 6. 环境与发布

模板默认只依赖Python3构建，浏览器运行不依赖构建工具。Node检查为开发可选能力，不要求学生安装。

不把某个助手的目录、账号、Sites标识、认证令牌或端口写入便携代码。构建路径以脚本自身目录为准。

交付时保持用户要求的范围：只要HTML就给HTML；要求源码或Skill再打包。在线发布使用当前宿主允许的工具，保留已有站点身份和访问范围。无发布能力时，文件交付仍应完整，不能编造“在线版已上线”。

宿主无法进行浏览器检查时，列出未验证项，不能用静态搜索和单元测试替代实际界面验证的结论。
