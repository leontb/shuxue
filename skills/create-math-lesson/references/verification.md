# 验证清单与结论边界

## A. 数学

- [ ] 已将题干、批注、参考答案分开，并独立求解。
- [ ] 每个量与单位正确，比较基准明确。
- [ ] 分数的“多/少/是”区别明确，每格对应量确定。
- [ ] 运动变量的计时起点正确，延迟与折返区间完整。
- [ ] 端点、零值、相遇前后、所有分支和全部解均检查。
- [ ] 变式重新求解，没有沿用原题解数或套错基准。
- [ ] 错项确实错误且有诊断价值，没有多个同样正确的选项。

记录关键值和独立预期，不用同一段实现生成“标准答案”再断言它等于自己。

## B. 图形与表达

- [ ] 图中的长度、面积、份数与单位有定义。
- [ ] 动画揭示了算式为何成立，不只是装饰或移动文字。
- [ ] 标签、图形和数值来自同一状态。
- [ ] 未按比例的图明确标记，不能用其读数。
- [ ] 相交、贴近、负数和端点位置的标签可读。
- [ ] 正确反馈自动消失后，关键解释仍可见或能回看。
- [ ] 总结是一图关系，不是把长文章分装进卡片。

## C. 互动

- [ ] 主讲解和训练均为选择题。
- [ ] 正确答案约600毫秒后只推进一步。
- [ ] 错答留步，提示解释错误，并允许重选。
- [ ] 连点不会跳步或创建多个后续动作。
- [ ] 改选、重播、回看、重置、隐藏取消旧推进。
- [ ] 动画暂停与答题推进使用独立计时管理。
- [ ] 最后一步到训练一，训练一到训练二，训练二完成后停止。
- [ ] 重置后所有选择、动画和训练状态回到初始。
- [ ] 键盘激活与焦点转移可用。
- [ ] 减少动态效果模式下仍可完成全流程。

## D. 离线与展示

- [ ] 无必需CDN、外部字体、远程图像、API和邻接文件。
- [ ] 下载按钮生成的文件确实保留脚本与样式。
- [ ] 打开实际导出文件，从初始状态完整作答。
- [ ] 在待推进或播放中下载，重开不会自动跳题。
- [ ] 手机最密集图与桌面均检查，没有横向溢出和小字不可读。
- [ ] 本地源码可在新的路径下构建，不包含原作者绝对路径。
- [ ] 在线URL若提供，确实来自成功发布。

## E. 教学效果（单独记录）

- [ ] 学生能说明每个格子、点或条代表什么。
- [ ] 学生能用一句话解释关键算式。
- [ ] 学生能识别一个典型错误，而非只记正确选项位置。
- [ ] 学生能独立完成改变条件或问法的训练。

没有真实学生试用时，E项保持“待验证”。技术与数学核验不等于学习效果研究。

## 自带检查的范围

- check_delivery.py：静态检查单文件结构、常见依赖、填写控件、下载入口等。
- check_engine.cjs：验证模板控制器的推进与取消行为，不能证明修改后的任意UI都正确。
- 完整折返示例的check_math.js：检查该示例的关键状态与边界，不能替代新题的数学验证。
- 任何检查失败时修复对应问题，再做必要的定向复测；不要为显得严谨重复无关测试。
