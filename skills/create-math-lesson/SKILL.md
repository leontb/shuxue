# 数学动画互动课件

把“为什么这样算”变成学生能观察、选择、回看的过程。先核对数学，再设计教学，最后实现页面。默认沿用下面约定；服从用户本次明确要求。

## 固定交付约定

- 默认面向六年级；采用学生已掌握的算术、图形与关系推理。
- 每步只解决一个关键判断，通常4～6步；按真实推理调整，不凑步数。
- 讲解和两道训练都用选择题；默认单选，选项3～4个，不要求填写。
- 选对后显示短反馈，约600毫秒自动进入下一步；选错留在原题，给针对性提示。
- 不设置必须点击的“下一步/下一题”按钮。保留回看、暂停、重播和关键时刻选择。
- 让主要推理在图示中持续可见；600毫秒的反馈只确认要点，不承载首次出现的长解析。
- 下方放一张紧凑的数学关系图和两道有变化的训练，不堆大段“数学思维”说明。
- 交付独立HTML，内嵌脚本、样式及图形，带“下载HTML”按钮；打开下载文件从初始状态开始。
- 只在具备相应能力和用户授权时发布在线版。用户要求仅文件时不发布；没有部署能力时交付完整本地文件并说明限制，不编造链接。

## 1. 先完成数学核验

1. 读取原题，记录已知量、单位、所求量、比较基准、启动与折返条件、变量范围。
2. 将印刷题干与手写批注、图片附带答案分开；先独立求解，再核对答案。
3. 对影响答案的模糊条件先辨认；仍无法确定时明确缺口，必要时只问一个关键问题。不要猜数后当成原题。
4. 建立纯数学模型，生成关键状态与边界表。优先保留分数精确值，显示时再取小数。
5. 检查完整解集：分时段、分方向、分比较基准；相遇前后、折返瞬间、端点、零值均考虑。
6. 检查含义与单位，即使两个错误算式碰巧数值相同，也不能视为正确。

阅读 [teaching-method.md](references/teaching-method.md) 的方法选择表。遇到运动、分数基准变化等题型，再读 [worked-patterns.md](references/worked-patterns.md) 的相应部分。

## 2. 写教学分镜，再写页面

为每步填写以下五项，可使用 [storyboard-template.md](references/storyboard-template.md)：

| 字段 | 要求 |
|---|---|
| 本步判断 | 学生这一步应想明白什么 |
| 核心画面 | 图上哪些对象对应题目的哪些量 |
| 变化 | 移动、分组、配对、增减或高亮解释了哪一个关系 |
| 一句解释 | 用短句说清图与算式的联系 |
| 选择与反馈 | 正确项、错误项所代表的误解、针对性提示 |

逐步检查：删掉画面后，学生是否会失去一项必要信息？若不会，改成能解释推理的图或直接删掉。
避免把大量文字塞进图框，也不要把文字顺序出现当成数学动画。

## 3. 选择实现方式

### 新课：使用轻量模板

运行以下命令，令 SKILL_DIR 指向本文件所在目录：

```bash
python3 "$SKILL_DIR/scripts/new_lesson.py" --out /absolute/path/to/new-lesson
python3 /absolute/path/to/new-lesson/build.py
```

目标目录必须不存在或为空。模板中的阅读页数题只是可运行样例；替换题干、所有步骤、图形、答案、总结和训练后再交付，不只替换标题与数字。

先读 [template-api.md](references/template-api.md) 和模板中的 `lesson.js`，明确内容与控制逻辑的接口。保留经过验证的自动推进、取消计时、下载与可访问性行为。按题型重写数学与图形，不强行套用条形图。

### 更新已有课件

读取现有源码与交互约定，保留已授权的题目、链接、状态入口和文件身份。只改用户指定的范围，随后验证受影响的数学与交互。不要为小修改重建无关页面或改换访问权限。

### 参考完整案例

用 [bouncing-reference.html](assets/bouncing-reference.html) 观察完整的动点折返课：分段、关键时刻、相遇前后、局部放大、漏解检查、一图总结与两道训练。把它当作结构与推理表达的参考，不把它的时间、坐标、速度或正确选项当成通用规则。

## 4. 实现互动与动画

阅读 [interaction-contract.md](references/interaction-contract.md)。

- 将数学函数、页面状态、动画进度与自动推进计时分开。
- 使用同一份数学状态更新点的位置、标尺、读数与说明。
- 新选择、回看、重播、重置、隐藏页面时取消旧推进，防止意外跳题。
- 正确反馈结束后只推进一次；最后一步进入训练一，训练一正确后进入训练二。
- 支持减少动态效果偏好；关闭自动动效时，静态关键帧仍完整解释关系。
- 确保手机字号、触控面积与图形标签可读；小屏可放大局部、分层显示，不能整图缩成小字。

## 5. 总结与训练

用图总结“本题实际用到的关系”：量→关系→运算→检验。每个节点附一个具体数量或本题例子。

设计两道训练：
1. 近迁移：沿用核心关系，改变数值、目标距离或观察时刻。
2. 改变条件或问法：改变比较标准、方向、出发时刻、所求量，或由求结果改为倒推。

独立求解两题，重新检查多解与边界，不沿用原题答案个数。给出可展开图解与按误解设计的错项反馈。

## 6. 验证与交付

阅读 [verification.md](references/verification.md)。只报告实际完成的验证。

```bash
python3 "$SKILL_DIR/scripts/check_delivery.py" /absolute/path/to/new-lesson/index.html
node "$SKILL_DIR/scripts/check_engine.cjs"
```

第二条验证模板控制器；若改了控制器，针对改后的文件重新测试。静态检查和模板测试不能证明新题数学正确、浏览器无缺陷或学生已理解。

在可用浏览器中走完主讲解和两道训练，检查至少一个手机宽度及桌面宽度，实际打开下载文件。
没有浏览器能力时，不安装不必要依赖或伪称验证通过；完成可执行检查并说明未覆盖项。

交付时提供：
- 可下载HTML；用户要求时提供源码包。
- 已实际发布的在线链接，或明确本次仅提供离线版。
- 简短说明关键教学处理和重要验证边界。用户只要文件时保持简短。
